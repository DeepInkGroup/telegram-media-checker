# Telegram media checker

Requires Node.js 18+ and dependencies installed with `npm install`. Set `TELEGRAM_BOT_TOKEN` and run `npm start`. Send a photo, video, or image/video document to the bot. Telegram may compress photos sent normally; send them as files to inspect the original. Telegram's hosted Bot API limits downloads through `getFile` to 20 MB; for larger files the bot reports the metadata Telegram provides.

Administrator 1061254944 can use `/admin`, `/users`, `/user ID`, `/ban ID`, and `/unban ID` in a private chat. User activity and block status are stored locally in `users.json` and begin accumulating when this feature is enabled. Blocking stops the bot from serving a user; it does not block them on Telegram. The users list shows the 20 most recently active users.

Use `/send ID message` to message one user and `/broadcast message` to message all eligible users. Messages can span multiple lines. Only users who have contacted the bot in private since messaging was enabled are eligible; locally blocked users and the administrator are excluded from broadcasts. Telegram may still reject delivery, and the bot reports the outcome.

Free users can check 50 media items per day and Pro users 200. Existing and new users default to Free, including the administrator. Limits reset at midnight in Asia/Tehran. Each accepted image or video counts as one check, even if only Telegram's metadata is available; unsupported files do not count. Users can see their plan and usage with `/status`. The administrator can set a registered user's plan with `/plan ID free` or `/plan ID pro`; changing plans preserves the day's usage. `/user ID` shows the current plan and usage. Daily counts start when this feature is enabled.

The admin can change plan limits using `/limit free NUMBER` or `/limit pro NUMBER` (0–1,000,000), reset one user's daily usage with `/reset ID`, or reset everyone's daily usage with `/reset all`. These commands do not change plans or lifetime counts. Use `/bot off` to pause automatic replies to other users, and `/bot on` to resume; admin commands and admin media checks remain available. The setting survives restart. Admin-initiated `/send` and `/broadcast` still work while replies are off. Settings are persisted in `settings.json`. Media details include aspect ratio, megapixels, codec profile, bit depth, color space, container and audio bitrate when available.

To require channel subscriptions, first make the bot an administrator in each channel. In the admin private chat use `/channeladd @username` for a public channel, or `/channeladd -100CHANNELID https://t.me/+INVITE` for a private channel. An optional invite link can also be supplied for a public channel. `/channels` lists requirements and their IDs; `/channelremove ID` removes one. Up to 10 channels may be required. Users must be members of all required channels before using the bot; the administrator is exempt. Membership is verified for each request, and verification errors temporarily prevent access. Join requests must be approved before membership can be verified. Existing messages to the bot are not automatically reprocessed after joining.

## Deployment

`render.yaml` configures a paid Render background worker and a persistent disk. Provide `TELEGRAM_BOT_TOKEN` as a secret environment variable; do not commit it. `DATA_DIR` points to the disk, where `users.json` and `settings.json` are stored. An existing installation's two data files must be transferred securely to the mounted disk before switching over, otherwise it starts with empty users and default settings. Stop the previous instance before running the new one: Telegram allows only one polling instance per bot. Persistent disks and background workers incur charges; check Render's current pricing before deployment. A disk protects data across restarts and deployments, but is not a backup.
